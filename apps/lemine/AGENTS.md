## Что это

LeMine — личный некоммерческий лаунчер Minecraft для одного пользователя. Сделан на основе форка монорепозитория Modrinth (`D:\www\LeMine`), но концептуально это новый лаунчер. С Modrinth его связывает только одно: моды, шейдеры и ресурспаки скачиваются через их API.

Пользователь русскоязычный и не программист. Отвечать ему по-русски, простыми словами, без жаргона. Работать постепенно, по одной задаче.

### Требования (закреплены пользователем)

- Без рекламы, телеметрии и любой передачи данных.
- Без модпаков, датапаков и серверов-каталогов. Есть только свои сборки, в них моды, шейдеры и ресурспаки из Modrinth.
- Интерфейс только на русском. Название — LeMine.
- Вход по нику (офлайн) — основной. Вход через Microsoft остаётся опцией. Входа в Modrinth нет.
- Discord RPC остаётся. Импорта из других лаунчеров нет.
- Скин на главной показывается в 3D по нику:
  - офлайн — скин игрока с тем же ником через `mc-heads.net`;
  - Microsoft — надетый скин.

## Архитектура

| Часть | Путь | Роль |
| --- | --- | --- |
| Оболочка Tauri 2 | `apps/app` | Окно, команды-плагины (`plugin:instance|…`, `plugin:auth|…` и т. д.), процесс `theseus_gui` |
| Rust-ядро `theseus` | `packages/app-lib` | Сборки, установка, запуск игры, аккаунты, скины, логи |
| **Новый фронтенд** | `apps/lemine` (`@lemine/app`) | Vue 3 + Vite + TypeScript, весь интерфейс LeMine |
| Старый фронтенд Modrinth | `apps/app-frontend` | **Не используется.** Из него нужна только папка `src/generated/app-events` (алиас `#events`), а ещё он служит справочником по вызовам ядра |
| Брендинг | `branding/` | `Vector.svg` — исходный логотип, `app-icon.svg` — иконка приложения |

Связь фронтенда и ядра:

- Команды вызываются через `invoke`, обёртки лежат в `src/api/core.ts`.
- События идут через `tauri::ipc::Channel`, кодек postcard: `src/api/events.ts`, `src/api/event-codec.ts`.
- Канал передаётся в `initialize_state` при старте. После перезагрузки окна ядро заменяет канал новым, и это нормально.

### Ключевые доработки ядра

- **Офлайн-вход** (`packages/app-lib/src/state/minecraft_auth.rs`, `login_offline`):
  - признак офлайна — пустой `refresh_token`, проверка через `Credentials::is_offline()`;
  - access token равен `"0"`, `user_type` при запуске — `legacy`;
  - UUID вычисляется как `md5("OfflinePlayer:" + ник)`.
- **Убрано:**
  - реклама: плагин ads и окна `ads_*`;
  - аналитика посещений серверов;
  - отправка игрового времени (`try_update_playtime_by_instance_id` только помечает время, ничего не отправляет);
  - `post_json`.
- **`tauri.conf.json`:**
  - `identifier`, `productName` и `mainBinaryName` — `LeMine`, данные лежат в `%APPDATA%\LeMine`;
  - CSP ужесточена: `font-src 'self' data:`, `script-src 'self'`;
  - фронтенд берётся из `../lemine/dist`, dev-команда — `pnpm --filter @lemine/app dev`.
- **Цензура логов** (`packages/app-lib/src/api/logs.rs`) пропускает офлайн-аккаунты, иначе токен `"0"` заменял каждую цифру ноль в логе.

## Правила дизайна

- **Стиль:** как в проекте Sakeva (`D:\www\SakevaFull`), но розовый акцент заменён на тёмно-фиолетовый `#7D61E0`.
  - Фон — нейтральный тёмный, `#101010` и `#181818`.
  - Текст белый.
  - Акцент только в мелочах. Без свечений.
- **Шрифты:**
  - заголовки — Montserrat 800;
  - текст — Onest;
  - логотип и ник — Pixelify Sans.
- **Рамок нет нигде.** Обводок фокуса тоже нет: `outline: none`. Выделение делается фоном, а у выбранных карточек — `inset box-shadow` акцентом.
- **Токены** в `base.css`:
  - фоны и поверхности: `--bg`, `--surface-1…4`;
  - текст: `--text`, `--text-2`, `--text-3`;
  - акцент: `--accent`, `--accent-soft`, `--accent-text`;
  - статусы: `--danger`, `--success`;
  - радиусы: `--radius-md|lg|xl`;
  - шрифты: `--font`, `--font-heading`, `--font-pixel`.
- Вместо атрибута `title` используй только `v-tip="'текст'"`: стандартные подсказки Windows пользователю не нравятся.
- **Кнопки:** вторичная кнопка рядом с основной должна быть того же `size`.
- **Модалки «с характером»** (создание сборки, гардероб) открываются с `UiModal bare`, а цветную шапку они рисуют сами.
- **Иконки:** `lucide-vue-next`. Символы иконок сборок лежат в `src/assets/instance-icons`. Символы с брендом Modrinth удалены.
- **Скриншоты:** когда пользователь говорит «скучно», он ждёт живой, игровой интерфейс: цветные шапки, крупную типографику, карточки, быстрые действия. Не ограничивайся перекрашиванием.

## Грабли

- HMR: модули с общим состоянием (`store`, `events`, `active-skin`, `toasts`, `ui-state`) при изменении перезагружают окно целиком через `import.meta.hot.accept(() => location.reload())`. В Vite 8 нет `hot.decline()`.
- Ядро зовёт NeoForge `neo`: `metadata_get_loader_versions` требует `loader: 'neo'`. Маппинг сделан в `core.metadata.loaderVersions`.
- `jre_get_max_memory` возвращает **килобайты**. `core.java.maxMemory()` переводит их в мегабайты.
- Расширение типов `declare module 'vue'` клади только в файл-модуль, например `directives/tooltip.ts`. В `env.d.ts` оно затирает весь модуль `vue`.
- Всплывающие панели (`UiPopover`) телепортируются в `body` с `position: fixed`, иначе их обрезают модалки с `overflow`.
- Генерированные иконки создаются командами `instance_cache_generated_icon` и `instance_edit_generated_icon`. Байты PNG символа передаются из фронтенда.
- Обновление мода: `instance_update_project`.

### 2026-10-24 — Замер производительности главного экрана (только тест, код не менялся)
- Как мерили: временный модуль `src/dev/home-perf.ts` (после замера удалён вместе с вызовом из `HomeDiorama`). Он 5 секунд считал реальные интервалы `requestAnimationFrame` и время `viewer.draw()`, затем на паузе рендерил по 90 кадров при pixelRatio 1 / 0.75 / 0.5 с синхронизацией GPU (`readPixels` одного пикселя), читал `renderer.info` и выводил строку `[home-perf]` в консоль (она попадает в лог `pnpm app:dev`).
- Машина: i5-12400F, RTX 3050 (ANGLE D3D11), экран 1920×1080 при 180 Гц, DPR 1, холст 1920×1032.
- Результат:
  - реально 180 fps (столько, сколько даёт монитор), интервал 5,56 мс, p95 5,7 мс;
  - CPU на кадр (анимация и отправка рендера) — в среднем 1,2 мс, p95 1,8 мс;
  - рендер с ожиданием GPU: 2,86 мс при 1920×1032, 2,5 мс при 1440×774, 2,27 мс при 960×516. Разрешение почти не влияет — сцена упирается в геометрию и число вызовов отрисовки, а не в пиксели;
  - сцена: 231 вызов отрисовки, ~255 тыс. треугольников, 48 геометрий, 42 текстуры, 11 шейдерных программ.
- Главные причины нагрузки:
  1. `buildTerrain` заполняет каждую колонку горы блоками до самого низа (до 18 в глубину), хотя видна только верхушка и открытые бока. Это ~20 тыс. кубов, почти все невидимы.
  2. Рендер идёт непрерывно с частотой монитора (180 кадров в секунду на 180 Гц) даже на неподвижной сцене. Он не останавливается, когда окно не в фокусе или запущена игра — лаунчер за игрой отнимает GPU у Minecraft (пока не свёрнут).
  3. Поверх каждого кадра — проход FXAA на весь экран (skinview3d `EffectComposer`).
- Оценка для слабого ноутбука (Celeron/Pentium или старый i3 с Intel UHD 600/620, ~15–25 раз слабее RTX 3050 и в 4–8 раз медленнее i5-12400F в один поток): ~20–35 мс на кадр, то есть 30–45 fps с заметными подёргиваниями. GPU всё время под 100% — шум, нагрев, быстрая разрядка батареи.

### 2026-10-24 — Оптимизация главного экрана
- По результатам замера (см. запись выше) главная облегчена без изменений в композиции:
  1. **Невидимые блоки горы.** `buildTerrain` под верхним блоком строит только ту часть колонки, что выступает над самым низким из четырёх соседей (`neighbourHeight`; за краем карты высота 0, поэтому края остаются полными). Треугольники: ~255 тыс. → ~69 тыс., вызовы отрисовки: 231 → 211. Внешне гора не изменилась.
  2. **Ограничение частоты кадров.** `limitFrameRate` подменяет `viewer.draw` у skinview3d: лишние обновления экрана пропускаются (только перезаказ `requestAnimationFrame`, без анимации и рендера). Не больше 60 fps, пока окно в фокусе, и 24 fps, когда не в фокусе. На мониторе 180 Гц нагрузка упала втрое.
  3. **Пауза.** Вычисляемое `paused` = страница скрыта (KeepAlive: `pageActive`) или выключена «Живая главная», или запущена игра и окно лаунчера не в фокусе. Переключается через `viewer.renderPaused`; при постановке на паузу дорисовывается последний кадр. Фокус окна отслеживается через `getCurrentWindow().onFocusChanged`.
  4. **Разрешение.** `pixelRatio: Math.min(devicePixelRatio, 1.25)` — на ноутбуках с масштабом 150–200% холст не рендерится в полном физическом разрешении. На экранах со 100% ничего не меняется.
  5. **Размытие под плашками.** `backdrop-filter: blur(12px)` убран с полосы шапки и с панели запуска главной. Фон `--panel` и так почти непрозрачный, а размытие поверх анимированного WebGL пересчитывалось каждый кадр.
- Настройка «Живая главная» (Настройки → Лаунчер, `lemine:animated-home`, `src/composables/performance.ts`). Выключено — сцена стоит неподвижной картинкой; кадр дорисовывается после загрузки текстур и скина и при изменении размера окна.
- FXAA оставлен: замер показал, что разрешение почти не влияет на время кадра, а без сглаживания края блоков рябят.
- Повторный замер (окно 1326×800, не в фокусе): 69 тыс. треугольников, ~23 кадра в секунду при обновлении экрана 180 Гц, рендер с ожиданием GPU 2,3 мс.
